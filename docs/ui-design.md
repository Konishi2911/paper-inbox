# UI設計

## 配置と責務

低彩度の青・グレーを基本に、折り畳み可能な左メニュー、中央の文献一覧、右の詳細・機能画面を維持する。装飾より情報密度・視認性・操作数を優先する。将来のInbox、お気に入り、未読、候補、タグ/コレクション、設定は、必要な保存・検索機能が揃ってから追加する。

MainWindowは状態、画面遷移、Rust接続、コンポーネント間の配線を担当する。子は表示と局所操作のみを担当し、callbackで意図を返す。DBや全体遷移を子へ移さない。`in` は親からの読込、`in-out` と `<=>` は共有編集値、`private` は子内部の状態に使う。`<=>` の片方向化は入力と保存値の食い違いを生むため、切り出し時に契約を検証する。

## 現在のファイルと接続

- `theme.slint`: 色トークン。OSテーマ/ダークモードの切替は未実装。
- `types.slint`: `NavigationAction`、`AuthorAction`、`DetailView`、共有行モデル（著者・文献・候補・提案・版）。MainWindowから再エクスポートし、Rustは生成Enumを利用する。
- `components/paper-card.slint`: タイトル・著者・年・キー、選択、hover、出力チェック。通常72px、出力108pxはpreferred-heightの目安。内容が長ければ暗黙のレイアウト最小サイズを優先して高さを伸ばし、見切れを防ぐ。
- `components/sidebar.slint`: 操作通知と表示。登録の入口は「文献を追加」1つ。遷移・検索は親へ残す。
- `components/splitter.slint`: ドラッグ開始時の幅とウィンドウ上のポインター位置から幅要求を返す。
- `components/paper-detail.slint`: 保存済みの読取専用詳細。掲載情報の1行要約、著者の省略表示、識別子のコピー・開く、BibTeXコピー、アブストラクトの展開、個人情報（読書状態・お気に入り・アーカイブ・メモ）のその場変更を通知する。表示値は正常読込のreplyでRustが更新する。
- `components/author-editor.slint`: 1行1著者（種類・ORCIDは行ごとに展開）、追加・削除・上下、まとめて入力の通知。モデルの変更と貼付文字列の解析は親のRust処理に委ねる。
- `components/paper-editor.slint`: 左ラベル2列の編集フォーム、AuthorEditorとの接続、保存（Ctrl+S）・取消・削除復元の通知、保存エラーの表示。
- `components/paper-list.slint`: 検索、sort、archiveフィルタ、カード、page。条件とoffsetはMainWindowと共有し、選択・検索を通知する。
- `views/import-view.slint`: 統合登録画面（lookup-new）と既存文献の識別子取得。取得値は読取専用の項目別表示、登録時の個人入力（引用キー・読書状態・お気に入り・メモ）、手動入力への切替を通知する。`candidate-editor.slint`: 候補の提示項目と入力。
- `views/metadata-view.slint` / `proposal-view.slint`: 出典・版と現在/提案値、承認通知。承認判定はcore/storageに残す。
- `views/export-view.slint`: 出力設定。`dialogs/export-dialog.slint`: 書込み前のpreview・警告・上書き確認。
- `dialogs/about-dialog.slint` / `confirm-dialog.slint`: 謝辞と共通確認表示。実際の状態変更はMainWindowへ通知する。
- `main.slint`: 3ペイン構成、画面選択、親状態、各コンポーネントの接続。`ui.rs` がworker要求とreplyを接続する。

著者操作の引数順は `(AuthorAction, row_index)`。移動・削除には実際の行番号を渡す。著者フィールド指定の数値は現在残っているが、本工程で無関係なAPI変更を一括導入しない。

## 閲覧・編集の契約（Step 8実装済み）

1. 既存文献を選ぶと保存済みの読取専用詳細を表示する。著者を含む表示値はRustの同一replyから更新する。
2. 「編集」で編集へ、新規登録は直接フォームへ進む。削除済みは編集不可で復元可能な表示を維持する。
3. 保存失敗ではフォームと入力を維持する。保存成功かつ正常再読込が届いた時点で閲覧へ戻る。
4. 保存後の再読込失敗は保存済みであることを示し、再読込まで重複保存しない。成功表示だけで閲覧へ移さない。
5. キャンセルは未保存確認とDB再読込を使い、保存前の値を閲覧に残さない。破棄を取り消したらフォーム・入力を保持する。
6. 別文献、新規、候補画面、再接続でも前文献の編集状態を持ち越さない。

Rustの `apply_reply` は完全なEditorViewが届いたときだけ `edit-mode` と著者表示を更新する。既存IDは閲覧、新規は編集とし、エラーreplyでは入力とmodeを保持する。保存成功後の再読込失敗は `load-required` と既存フォームを保持する。単体試験でreplyの境界を、`editor_window_contract` で実ワーカー・画面操作の保存/取消/競合/削除復元を検証している。

## PaperEditorの接続（Step 9）

編集値とdirtyは `MainWindow <=> PaperEditor` の双方向バインディングで共有する。タイトル入力のアクセシビリティ操作から親の値とdirtyが変わることを結合テストで確認する。読取専用フラグやAuthorRowモデルは `in property` とし、著者行の変更は生成AuthorActionと実際の行番号をcallbackで通知する。

PaperEditorにはDB・画面遷移・編集モード決定を置かない。保存、再読込、候補確認、取消、削除/復元、削除確認への応答をMainWindowへ通知し、親が既存のrequest-navigationとRust callbackを使う。AuthorRowは循環importを避けてtypes.slintへ移し、MainWindowから再エクスポートするのでRustの公開名は維持する。Step 10で著者をAuthorEditorへ分離し、同じcallbackの経路を維持した。

## 画面状態（Step 13）

MainWindowの共有 `detail-view: DetailView` だけで右ペインの表示を選ぶ。RustはSlintの生成Enumを使い、別のcurrent-screenやEnumを二重定義しない。

| DetailView | 表示 |
| --- | --- |
| Empty | 初回準備前等の案内 |
| PaperDetail | 保存済み文献の閲覧 |
| PaperEditor | 新規・編集。削除済みは同じフォームを読取専用にして復元を提供 |
| Import | 新規/既存への取得。lookup-newは取得用途を表すデータcontext |
| MetadataReview | 候補・提案・版の確認 |
| MetadataCandidateEditor | 同じMetadataView内の候補入力 |
| ExportSettings | 出力対象・保存先・項目の設定 |
| ExportPreview | 確認待ちpreview |

旧 `lookup-open`、`metadata-open`、`candidate-form-open`、`export-confirm`、`export-settings-open`、`editor-visible`、`edit-mode` は `out property` の読取専用派生値で、独立した可変状態ではない。既存の読込API名を維持するためのもので、Rust側のsetterは使わない。実際の表示条件はDetailViewを直接比較する。

`busy`、`ready`、各draftの`dirty`、`load-required`、About/削除/破棄/関連付け確認は画面選択と独立した状態として維持する。現在の閲覧文献とBibTeX選択集合も独立し、一般の複数選択化はStep 14で仕様を決める。

### 成功・失敗・戻る

- ローカルな「編集」や出力設定の開閉はMainWindowでEnumを変更する。保存・再読込・取得先切替の結果はRustのreply反映後に一度だけ画面へ適用する。
- DB読込を要求しただけで現在の画面を消さない。未保存破棄を承認しても、移動先の読込が失敗したら元の画面・入力・dirtyを保持する。成功時に新しい読込値とdirtyを反映する。
- `export-return-view` は設定を開く前の戻り先、`preview-return-view` はpreviewを開く前の戻り先。表示判定に使う別のcurrent-screenではなく、履歴だけを保持する。
- 編集/候補/取得から出力設定→preview→キャンセル→設定を閉じる、という入れ子でも元のdraftを復元する。アプリcallbackが編集から直接previewを開いた場合も実際の元画面へ戻す。
- 書誌情報取得の取消は、新規なら新規フォーム、既存なら候補確認へ戻す。保存失敗では現在の画面と入力を維持する。保存成功・再読込失敗では編集を維持して重複保存を防ぐ。

`detail_view_window_contract` はEnumと実際に存在する画面コンポーネントを両方確認し、右ペインの排他性、戻り先、dirty保持、失敗遷移を試験する。`paper_list_window_contract` は子の入力から親の検索条件・offset・通知が変化することを検証する。

## 幅変更とBinding Loop

一覧は `preferred-width`、一覧最小260px、詳細最小360px、Splitter幅8pxを使う。親幅に基づく上限は `resize-requested` 内で命令的にclampする。子幅のリアクティブな上限が親の最小幅を再計算して循環する構造を避ける。

Splitterはローカルmouse-x単独ではなくabsolute-positionとの和を使う。ドラッグ、縮小、サイドバー開閉、長文・多数著者で最小幅と追従性を検証する。静的な式の確認やcargo checkのみでBinding Loop解消済みとは判断しない。

## U1: 統合登録画面

登録の入口をサイドバーの「＋ 文献を追加」1つにした。画面を開くと識別子欄へ`init`でフォーカスし、Enterで取得する。取得結果が届くと引用キー欄が生成され、その`init`でフォーカスを移すため、続けてEnterで登録できる。Slintでは条件付き要素（`if`）の内部要素を外から参照できないため、要素自身の`init`で生成時にフォーカスする方式を採用した。

取得した書誌項目は読取専用の`[LookupField]`で表示し、手動値に変換しない。手動値にすると出典が失われ、以後の外部更新がすべて承認待ちになるためである。読書状態・お気に入り・メモは書誌情報ではないので、`RegisterMetadataCandidate`と同じ一括トランザクションで`SetReadingStatus`等を適用する。引用キー不正などで失敗した場合は何も保存しない。

識別子のない文献は同じ画面の「手動で入力」から既存の手動フォーム（見出し「文献を追加（手動入力）」）へ移り、フォームからも「DOI / arXiv から取得に切り替え」で戻れる。未保存入力がある場合は既存の破棄確認を経る。閉じるボタンは確認なしで破棄するため、入力がある場合は「破棄して閉じる」と表示する。閉じた後は案内表示（Empty）に戻る。

検証: `unified_add_window_contract` で入口の一本化、初期フォーカスとキー入力、Enterのみの取得→登録、閉じる・手動入力への切替を、`lookup_window_contract` と `lookup_application_contract` で項目別表示・個人入力の一括保存・失敗時に何も残らないこと・出典維持を確認する。

## U3: 詳細画面と入力フォーム

詳細は保存済みの値だけを表示する。取得済みでも以前は表示されなかった出版社・巻・号・ページ・URL・アブストラクト・キーワードを表示し、掲載情報は「掲載先 巻(号), pp. ページ, 年・種別・出版社」の1行に要約する。要約、著者の省略（先頭3名＋他n名）、アブストラクトの300文字プレビューはRust（`detail.rs`）で計算し、正常読込のreplyで一度に反映する。

読書状態・お気に入り・アーカイブ・メモは書誌情報ではないため、詳細から直接保存する（`QuickChange`）。表示中の`PaperEditState`を期待状態として一括保存し、別の変更があれば競合として拒否する。トグル系の失敗は保存済みの値を再読込して表示を戻し、メモの失敗は入力を保持する。メモの編集中は既存の`dirty`を使うため、移動時の破棄確認がそのまま働き、即時操作は下書きを失わないよう無効にする。メモ編集状態（`notes-editing`）は正常再読込後にRustが解除する。

コピーは標準TextInputの`select-all()`と`copy()`を使い、クリップボード用の依存を増やさない。コピー元は非表示の読取専用TextInputに置く（U3dで操作ボタンの行へ移した。下記）。リンクは検証済みDOI/arXivから`https://doi.org/`・`https://arxiv.org/abs/`を組み立て、URLはhttp(s)で空白・制御文字のないものだけを、Slint経由で既に依存している`webbrowser`でシェルを介さずに開く。

フォームは詳細と同じ順序（書誌→識別子→内容→自分の記録）で、左にラベル、右に入力を置く。ラベルのTextは入力と同じ名前を持つため`accessible-role: none`にして重複を避ける。著者は1行1名とし、種類とORCIDは行ごとの「⋯」で開く。「まとめて入力」は「姓, 名」を`;`・改行区切りで受け、カンマのない英字名は最後の語を姓、それ以外は最初の語を姓とみなして行を追加する（保存前に確認・修正できる）。保存エラーはステータス行に加えて保存ボタンの上に表示し、成功した再読込で消す。`FocusScope`で子の入力から伝播したCtrl+Sを受けて保存する。新規登録で引用キーが空なら通常の提案規則で決め、保存済みキーは自動生成しない。

編集で変更したと判定する項目だけを`EditBibliography`にし、前後空白の違いでは改訂を作らない。空欄化は明示的削除として扱う。ScrollViewは`content-width: self.visible-width`で内容幅を表示幅に固定し、長いURLや区切りのない語で右側の操作が表示外へ押し出されるのを防ぐ。

検証: `paper_form_contract`で新項目の往復、未変更保存で改訂を作らないこと、変更項目だけが手動出典になること、URLのみの変更でDOIを保持すること、即時操作の競合・削除済み拒否、著者解析、要約とリンク検証を確認する。`detail_window_contract`で取得項目の表示、コピー→貼付、即時保存、メモの破棄確認と保存、Ctrl+Sとエラー表示・入力保持、一括著者入力、引用キー自動提案、最小幅1080×680で操作が収まることを確認する。

## U3c: 書誌情報・版画面の簡素化

文字量を減らし、判断に必要な値と操作だけを常時表示する。保存・承認の契約（判断の一時保持と「判断を適用」での原子的保存、stale提案の採用不可、正規版切替と項目採用の分離、手動値保護）は変更していない。

- ヘッダー: 「文献へ戻る」と文献タイトルの1行、その下に「DOI / arXiv で取得」「候補を手入力」「表示を更新」の1行。説明文は置かない。
- 提案一覧: 見出し「更新の提案」の横に「n 件 · 要確認 n · 判断済み n」。フィルタ・一括操作・「判断を適用」は1行のツールバーにまとめ、提案が0件のときはツールバーごと隠す。「リセット」は判断がある間だけ表示する。
- カード: 見出し行は項目名、変更種別と「要確認」のバッジ、長文の「全文を表示」。理由は要確認のときだけ1行表示する。現在値・提案値は見出しと情報源を同じ行に置く。単語差分と出典（改訂ID・レコード・取得日時など）は「詳細」に集約する。選択中の判断は該当ボタンの強調（`primary`）で示し、「判断: …」の文は廃止した。「判断を取り消す」は判断済みのときだけ表示する。長文トグルを見出し行に置くのは、展開後に長文の下へ押し出されて折りたためなくなるのを防ぐためである。
- 候補・版: 1件1枠で、1行目にタイトル、2行目に「情報源 · 版の種類 · 同一性 · 状態 · DOI · arXiv」を存在する項目だけ`·`で連結する（Rustの`join_present`）。操作は右端の「関連付ける…」「正規版にする…」。正規版は「正規版」のラベルで示す。「正規版にする…」は従来どおり切替の提案を作るだけで、承認は提案一覧で行う。
- 候補の手入力: 説明を1行にし、チェックボックスと入力欄を同じ行に置く。情報源名は「その他」のときだけ表示し、概要欄はチェック時だけ表示する。記録ID・更新日時は末尾の任意欄にまとめた。アクセシブル名は従来の「タイトルを提示する」等を維持する。
- 値の表示: 出版種別はRustのDebug表記ではなく、編集フォームと同じ日本語ラベル（`publication_type_label`）で表示する。長文プレビューの末尾は「…」のみとし、全文はボタンで開く。

検証: `metadata_diff_window_contract`で詳細の開閉、判断の取り消し（未判断に戻る）と未判断時に表示されないこと、長文の展開・折りたたみ、左右/上下配置を、`ui_metadata`の単体テストで要約行の連結と出版種別ラベルを確認する。既存の`metadata_window_contract`・`metadata_resolution_window_contract`は文言変更後も通過する。

## A3: PDF添付のUI

PDFの主操作は、U3dの操作ボタンの行の先頭（強調表示）に置く。添付がないときは「PDFを添付…」、あるときは「PDFを開く」（最初の、ライブラリに実在するファイル）になる。管理用の一覧は、1件以上あるときだけその下に出し、各行に名前、サイズと追加日、「開く」「取り外す」を並べ、見出し横のボタンは「追加…」になる。

取り外しは行内で1回だけ確認する（「取り外しますか？ [取り外す] [やめる]」）。確認状態は行の局所状態で、Rustには持たせない。確認中は「開く」を隠し、誤って開く・外すを続けて押す余地をなくす。外してもファイルは残る旨をステータスに表示し、削除は別画面に分ける。

PDFの行は編集の再読込のたびにRustが一緒に送る（`fill_attachments`）。再読込の経路が増えても一覧が古くならない。サイズ・追加日の文は`detail.rs`で作る。ライブラリ内のファイルが見つからない行は理由を表示して「開く」を無効にする（存在確認は読み込まずに行い、破損の検査は開くときに行う）。保存の操作と同じく、メモの下書きがある間は添付・取り外しを無効にする（再読込でメモが失われるため）。

ファイル選択はOS標準のダイアログ（`rfd`）で、UIスレッドで呼ぶ。テストでは`attach_with_providers`でダイアログ関数を差し替え、ボタン操作から添付までを通す。Slint 1.18.1の`DropArea`は部品としてあるが、winitバックエンドが外部アプリからのファイルドロップを受け取る実装を持たないため、ドラッグ＆ドロップによる添付は採用していない。

「未使用PDFの整理」は右ペインの排他画面（`DetailView.attachment-cleanup`、`NavigationAction.attachment-cleanup`）で、サイドバーから開く。入力の未保存確認は他の画面と同じ経路で働く。画面は件数と容量を示し、「n 件を削除」を押したときだけ削除する。0件のときは削除ボタンが無効になる。閉じると、開いていた文献があればその詳細へ戻る。文献一覧から同じ文献を選び直したときに画面が切り替わるよう、`open-paper`の判定に整理画面を含めた。

検証: `attachment_window_contract`で、キャンセル時に何も起きないこと、PDFでないファイルの拒否、添付→一覧→DB保存、1080×680での操作の収まり、ファイル欠落時の表示、重複の拒否、下書き中の無効化、取り外しの確認と中止、ファイルが残ること、整理の件数表示と削除、整理画面から文献へ戻ることを確認する。`detail_view_window_contract`で整理画面が右ペインの排他画面の1つであり、未保存入力があると確認を挟むことを確認する。実際のダイアログとOSビューアの起動は自動テストに含めておらず、手動確認が必要である。

## U3d: 詳細画面の操作ボタンの行

DOI・arXiv・URL・引用キー・BibTeXの行ごとのコピー／開くをやめ、タイトル・著者・掲載情報の直下に1つの操作ボタンの行を置いた。識別子の5行ぶん（約200px）が減り、アブストラクトとメモが上に上がる。ユーザーが選んだ案（2026-11-17）に従う。

- 並び: 「PDFを開く／PDFを添付…」（強調）、「DOI ↗」、「BibTeX ⧉」、「引用キー ⧉」（ボタンにキーの文字を表示）、「⋯」。
- リンク: 1クリックで開くのはDOI、なければarXiv、なければURLの順で最初の1つ。ボタンの文字は実際のリンク先（DOI／arXiv／Web）にする。DOIは出版社のページとは限らないため「出版社」とは書かない。
- 「⋯」のメニュー（`PopupWindow`）: DOI・arXiv ID・URLのコピー、1クリックのリンクに選ばれなかったリンクを開く操作。各項目に値を表示する。識別子が1つもないときは「⋯」とリンクのボタンを出さない。
- 引用キーは最もコピーされるため、メニューに入れず専用ボタンにする。コピーすると「〜をコピーしました。」をステータスに出し、何がコピーされたか分かるようにする。
- 識別子の値は、操作ボタンの下の薄い1行（`DOI … · arXiv … · URL …`）にも残す。確認用で、読み取り専用の入力欄なので選択して手動コピーもできる。行はRustの`identifiers_line`で作る。
- 幅: 右ペイン560px以上で1行、未満で2行（1行目にPDF・リンク・「⋯」、2行目にBibTeX・引用キー）。ペインの最小幅は360pxで、ラベル付きボタンは1行に約3つしか収まらないため。`wide`は親から渡すのではなく詳細自身の幅から求めるが、Slintのコンパイル時にBinding Loopは検出されなかった。
- 操作回数: 引用キーのコピー1→1、BibTeXのコピー1→1、DOI／arXiv／URLを開く1→1（最優先の1つ）または2、DOIのコピー1→2。
- メモの下書き中も、開く・リンク・コピーは有効（保存を伴わないため）。添付だけは下書きがある間は無効にする。

検証: `detail_actions_window_contract`で、識別子の有無ごとのボタン構成、DOI>arXiv>URLの優先、メニューの項目と値、開くコールバック、PDFの有無・欠落時の状態、1行／2行の切替と1080×680での収まりを確認する。`detail_window_contract`でコピー→貼り付けの往復（引用キー、メニューのDOI）とステータス文を確認する。

## ダークモード

色はすべて `theme.slint` の `Theme` に集約し、各色にライト値とダーク値を持たせる。切り替えは `Palette.color-scheme`（OSの配色設定に追従）で行い、画面側は分岐しない。標準部品（ボタン・入力欄など）も同じ設定に追従する。差分の色分けはラベルを併記しているため、色だけに頼らない。ダーク値の見た目・コントラストは実機で未確認。

## U4: 一覧の見通し

- 検索語は入力が300ms止まると自動で検索する。Enter・「検索」は即時。検索欄は処理中も無効にしない（入力中に焦点を失わないため）。
- カードの年・引用キーの行の右に、読書状態（未読は強調、読書中、既読は非表示）・★・PDFを表示する。
- 検索欄の下に「未読」「★」「PDFあり」の切替ボタン。押すと強調表示になり、複数は AND で組み合わさる。検索語・並べ替えと同様、変更すると読込件数を50件に戻す。

## U2: タグ（詳細とサイドバー）

- 詳細: 「タグ」欄にタグ名の入力、付与済みのタグをチップで表示（×で外す）、入力中は既存タグの候補を最大6件ボタンで提示する。Enterで追加（既存タグと同じ名前＝空白・大小・全角半角を無視して一致すれば再利用、なければ作成して付与を1トランザクションで保存）。候補は画面上のタグ一覧から作るので、入力はワーカーを待たない。付与・解除は即時保存のため、メモの下書き中は無効。
- サイドバー: 「タグ」見出しの下に `名前 (件数)` のボタン。押すと絞り込み（強調表示）、複数選ぶと AND。件数は表示中の文献だけ（削除済みは除外、アーカイブは設定に従う）。件数0のタグは、選択中でなければ隠す。「すべての文献」「削除済み」を押すとタグの絞り込みは解除する。
- 編集・ワーカー: 文献の再読込ごとにその文献のタグを、一覧の再読込ごとに全タグと件数を一緒に送る（添付と同じ経路）。タグ操作の失敗は理由を状態欄に出し、表示は変えない。
- 登録画面（取得結果の登録）: 「登録時の入力」に同じタグ欄を置く。まだ文献がないので、追加したタグ名は画面上に溜め（同じ名前は1つにまとめる）、「登録」を押したときに書誌情報・メモなどと同じ1回の保存で、既存タグの再利用または新規作成と付与を行う。使えない名前が1つでもあれば、文献ごと登録しない。閉じる・登録後は空に戻す。
- 未実装: 手動入力フォームでのタグ指定、タグの改名・削除、チップが多いときの折り返し（横スクロール）。

## ボタンの共通部品（AppButton / Chip）

標準の `Button` は塗り・角丸・状態の見た目を変えられないため、アプリ内のボタンはすべて `components/app-button.slint` の `AppButton` に置き換えた（標準 `Button` は使わない）。色はすべて `Theme` から取り、ライト／ダークで同じ部品が使える。

- 種類（`kind`）: `primary`（塗りつぶし。1画面1つの主操作）、`tonal`（薄い塗り。既定の副操作）、`outline`（枠線のみ。キャンセル・戻る・編集など）、`ghost`（背景なし。ツールバー、「…」、行内の小さな操作、サイドバーの項目）、`danger`（赤系。取り外し・削除）。`primary: true` も互換のために残している。`small`（高さ28px）、`align-start`（ラベルを左寄せ）、`icon`（ラベルと同じ色で着色する16pxのアイコン）。
- **透過に対応する仕組み（採用理由）**: ホバー・押下は背景色を塗り替えず、ボタンの上に `Theme.wash`（ライトは濃紺、ダークは白、塗りつぶしは白）の半透明の膜を8%／16%（塗りつぶしは12%／22%）重ねる。ボタン自身の背景が透明でも、色付き・グラデーションの背景でも、ライト・ダークのどちらでも同じ計算で効く。
- フォーカス: `FocusScope`（Tabで移動）で、フォーカス中はボタンの外側に太い輪郭を描く。Space と Enter で押せる。無効時は全体を40%に薄くする。
- アクセシビリティ: `accessible-role: button`、ラベルは `text`（個別に上書き可）、有効状態と既定操作を公開する。内部の `Text` は `accessible-role: none`（ラベルの重複を避ける）。既存の画面テストは名前と操作で見つけているため変更不要。
- `Chip`: 絞り込み用の丸いピル。オフは枠線のみ、オンは薄い塗りと太字。`accessible-checkable` / `accessible-checked` を公開する。一覧の「未読」「★ お気に入り」「PDFあり」に使う。
- 大きさ: 高さは固定（通常34px、small 28px）、幅はラベルに合わせる（レイアウトで勝手に引き伸ばされない）。

## PDFのドラッグ&ドロップ

- Slint の `DropArea` はアプリ内のドラッグ専用で、外部のファイルは受け取れない。そのため `slint` の `unstable-winit-030` 機能を有効にし、`on_winit_window_event` でOSのファイルドラッグ（`HoveredFile` / `HoveredFileCancelled` / `DroppedFile`）を受ける（`ui::install_file_drop`）。この機能は将来の Slint で変わりうるが、`Cargo.lock` で版を固定している。
- 対応環境: Windows、macOS、Linux の X11。Wayland は使っている winit 0.30 が対応しておらず、ドロップは届かない（添付ボタンは常に使える）。画面を持たないテスト用バックエンドでは何もしない。
- 動作: ドラッグ中は画面全体に枠と案内を出す（`drop-hover`、入力は奪わない）。ドロップすると `file-dropped(path)` が呼ばれ、拡張子が `.pdf`（大小無視）でなければ理由を状態欄に出す。PDFで、かつ文献の詳細を開いていて未保存の編集がなければ（`can-drop-attach`。添付ボタンと同じ条件）、添付ボタンと同じ検証・保存（`AttachPdf`）で添付する。それ以外は理由を状態欄に出す。内容は添付時にも署名で検査するため、拡張子だけ変えたファイルは拒否される。
- 複数ファイルは1つずつイベントが届き、2つ目以降は処理中のため受け付けない（状態欄に表示）。
- 新規登録（ドロップ）: 何も開いていない画面（起動直後の空の新規フォームを含む）か、追加画面でPDFをドロップすると、追加画面を開いてそのPDFを「登録時に添付するPDF」として保持する（`can-drop-new`。未保存の編集があるときは対象外）。識別子を取得して「登録」すると、文献の保存後に同じ検証でPDFを添付する。PDFの添付に失敗しても登録は取り消さず、状態欄に理由を出す（詳細画面から添付し直せる）。追加画面でもう一度ドロップすると差し替え、「取り消し」で外せる。閉じる・登録後は空に戻す。開いている文献の詳細画面へのドロップは、従来どおりその文献への添付になる（枠の案内文で区別する）。
- 未実装: PDFの内容からDOIを探して自動で取得する処理、手動入力フォームへの添付予定の引き継ぎ、一覧上に文献を選んでいる状態での新規登録（選択中は添付になる）。
- 未確認: 実際のドラッグ操作（OSのイベントは自動テストで再現できないため、ドロップ後の処理だけを `file_drop_window_contract` で検証）。
