# 設計判断

確定はユーザーが承認した方針、暫定は実装上の現在値、未確定は実装前の判断事項を表す。既存の詳細契約はリンク先を正とし、ここでは背景・採用理由・トレードオフを整理する。

| 判断 | 状態 | 背景・採用した設計 | 代替案・トレードオフ |
| --- | --- | --- | --- |
| ローカルファーストと軽量な境界 | 確定 | オフライン利用を基本にcore/portsと各アダプターを分離 | 全構造体の抽象化は学習・保守負担が大きいため避ける |
| 正規化SQL | 確定 | 書誌情報をSQL一本で扱い、履歴は不変スナップショット | 列+全体JSONは採用しない。テーブル・結合・移行は増える |
| 未入力と手動クリア | 確定 | 初回未入力は手動headなし、明示的クリアは保護 | 全項目に手動履歴を作ると補完まで承認が必要になる |
| 外部更新の承認と鮮度 | 確定 | 出典/レコード/更新日時/headで判定し手動値を保護 | 取得時刻優先は古い情報の再取得で上書きし得る |
| 候補の提示項目とID | 確定 | 未提示は変更なし、提示空値は削除提案。同ID/同内容は冪等 | 全書誌情報の単純置換は欠落と削除を区別できない |
| 関連付け・独立版・正規版 | 確定 | 同一性不明は保留。明示的関連付けと全項目承認。正規版切替は別承認 | 自動統合・一括置換は誤同定や手動値消失を起こす |
| 一括保存と競合 | 確定 | 文献全体と全headを照合し全コマンドを原子的に保存 | 項目ごとの独立保存より保守的に競合を拒否する |
| 引用キー | 確定 | 著者+年→代表語→2以降の番号。削除済みも予約。保存済みは自動変更しない | 文献更新連動の再生成は既存引用を壊す。ASCII化できない著者はAuthor |
| DOI/arXiv | 確定 | 接頭辞/公式URL/空白を除去、DOI小文字化、arXiv版保持。旧不正値は保持・警告 | 厳格読込のみでは旧DBが開けず、自動消去は情報を失う |
| 取得先と登録確認 | 確定 | DOI→Crossref、arXiv→公式API。新規はpreview確認、既存は候補へ | DataCite/任意URL/PDFは現段階の取得範囲に含めない |
| BibTeX | 確定 | UTF-8、保存済み対象、上書き確認、途中失敗で元ファイル保持 | 未保存内容や無確認上書きは採用しない |
| IDのDefault | 確定 | new()同様に新しいUUID | nilで未指定を表す方式は採用しない |
| UI構成と分割 | 確定 | 3ペイン、カードclick、親の遷移と子の表示を分離 | 1ファイル肥大化を段階解消。分割自体は目的にしない |
| 閲覧・編集 | 確定・Step 8実装済み | 選択は閲覧、新規は編集、保存/取消は正常再読込で閲覧へ | Step 9でEditor抽出、Step 13でDetailViewを導入。edit-modeは読取専用派生値 |
| 右欄の排他状態 | 確定・Step 13実装済み | Slint生成DetailViewを唯一の可変選択とし、旧boolは読取専用。独立busy/dirty/確認と戻り先履歴は別 | 複数の可変表示boolやRust側の別Enumは不整合を作るため採用しない |
| 幅とカード寸法 | 暫定 | 一覧380/最小320、詳細最小360、Splitter8、通常カード72を現在値とする | 全画面・言語・長文での適正値は実測で調整する |
| UX優先の開発方針 | 確定 | 最低限の実用化を目標に、日常操作の手数・視線移動・入力の簡便さを優先。順序はU1統合登録→U2タグ→U3詳細の即時操作→U4一覧→U5重複警告 | 整合性機能の拡張や構造整理は当面止める。書誌差分・同期・FTSは凍結 |
| 詳細の操作ボタンの行 | 確定・U3d実装済み（2026-11-17） | PDF・リンク・BibTeX・引用キーを1行のボタンにし、その他のコピーは「⋯」のメニュー。1クリックのリンクはDOI>arXiv>URL。識別子の値は薄い1行で残す | 行ごとのコピー/開くは縦に場所を取り視線が散るため。引用キーは最頻のコピーなのでメニューに入れない。DOIのコピーは1→2クリックになる |
| 詳細の即時操作とコピー | 確定・U3実装済み | 個人情報（読書状態・お気に入り・アーカイブ・メモ）は詳細から表示中の状態を期待値に直接保存。コピーは標準ウィジェットのクリップボード機能、リンクは検証済み識別子とhttp(s)のみを`webbrowser`で開く | 書誌項目のその場編集は手動値化・承認規則が絡むため編集フォームに残す。`arboard`等の追加依存は不要と判断 |
| 統合登録 | 確定・U1実装済み | 入口を1つにし、識別子取得を先頭、手動入力を同画面からの代替経路とする。取得値は読取専用で出典を保持し、個人入力のみ同一トランザクションで保存 | 取得値を手動フォームへ転記する案は自由度が高いが、出典を失い以後の更新が全て承認待ちになるため不採用 |
| タグの初期範囲 | 確定・U2未着手 | フラットなタグのみ。複数付与、補完入力、サイドバーで絞り込み。schemaの追加移行（v5は添付が使用したためv6） | 階層コレクションは移動・入れ子・削除規則の仕様と実装量が大きいため後回し |
| PDFの保存 | 確定・保存層・アプリ層・UI実装済み（2026-11-17） | DB外のSHA-256名ファイル（`library-files/`）＋attachments表。外してもファイルは残し、利用者の「未使用PDFの整理」で回収。取り込みは詳細からの手動添付のみ。添付は文献に付ける（版IDは任意）。開くときは元のファイル名で一時コピーを作りOS既定ビューアで開く | DB内BLOBは単一ファイルで原子的だが、DBが数GBになりバックアップ・同期が重くなるため不採用。元パス参照は移動・削除で壊れるため不採用 |
| ライセンス | 確定 | 独自コードMIT OR Apache-2.0、Slint Royalty-freeと公式謝辞 | 依存コードの条件は別。[ライセンス説明](licenses.md)を参照 |

## これから判断する事項

- 複数選択: Ctrl/Shift/全選択の意図は採用するが、ページ・検索・sort変更時の範囲、非表示選択の維持、全選択の対象をStep 14前に確定する。
- ショートカット: 入力欄のコピー等を優先し、一覧focus時だけの操作を定める。
- FTS5・仮想化: 描画仮想化とDBページ取得を分け、日本語検索と性能を評価する。
- 添付: 保存方式・回収・取り込み範囲・UIは確定・実装済み（上表「PDFの保存」、[UI設計](ui-design.md) A3）。未決: ドラッグ＆ドロップ（Slint 1.18.1のwinitバックエンドは外部からのファイルドロップを受け取らないため、対応を待つ）、PDFの存在・破損の一括検査、同じPDFが別の文献にある場合の通知（U5と合わせる）。
- PDFドロップの2領域（新規追加／現在の文献へ添付、2026-11-21判断）: 保留。winit 0.30（Slint 1.18.1）はファイルドラッグ中に位置を渡さず（Windowsの`drop_handler.rs`は位置引数を無視）、位置による領域判定ができない。Slintが位置つきのドラッグイベント（winit 0.31以降）に対応するまで待ち、現状の自動判定（開いている文献があれば添付、なければ登録時に添付）を維持する。検討した代替: ドロップ後の選択ダイアログ（迷う場合だけ／常時）、OSのカーソル位置の取得（Windows/macOS固有の`unsafe`、Waylandは不可）。Slintの更新時に再検討する。
- 同期: 自動同期と双方保持は方針。transport、クラウド、端末間因果依存、欠落イベント、削除競合、タグ集合、圧縮/GCは未決定。
- UI設定: 保存形式・互換性・配置を現在のCLI Configと分けて検討する。
- Dark mode: 標準widgetとThemeの整合、OS設定追従、利用者設定の優先順を決める。

重要な仕様・非互換変更は選択肢とトレードオフを提示して判断を求める。現在のDB・生成APIへ過去案を無条件に適用しない。


## Step 19の追加承認

- 確定: 判断は一時保持し、判断済みだけを原子的に一括適用。未判断を保留し、フィルタ/失敗時に判断を保持。
- 確定: カスタムUIは文字列/数値/DOI/arXiv。著者のカスタム編集は既存文献編集画面。タグ・添付は比較とテストまで。
- 実装: 手動値・競合・識別子・明示的削除・正規版切替は一括採用対象にしない。削除で理由が変わっても出典から保護する。
- 実装: 単語差分は上限付きLCSと通常Textの注記。Three-wayは因果関係を検証する比較のみで、同期や自動適用は行わない。
- 仕様・検証の詳細: [差分比較と判断](metadata-diff.md)。

- 確定: Windows と macOS（arm64・x86_64）の署名なしバイナリを zip で配布する。インストーラーは作らない。macOS の動作確認は配布前に作者が行う。
