# 書誌情報の差分比較と判断

## 対応範囲

Step 19の初期スコープを実装した。Two-way比較を実用画面として提供し、Three-wayは同期未実装時の準備・テストまでとする。

| 工程 | 実装と検証 |
| --- | --- |
| 19.1 | 既存のProposal/Revision/Provenanceと原子的コマンドを再利用 |
| 19.2 | 型付き変更判定。未提示・未設定・削除・空文字列を区別 |
| 19.3 | 現在/提案の左右比較。狭幅では上下 |
| 19.4 | 両側の出典・取得日時・情報源更新日時・改訂IDを展開 |
| 19.5 | 判断の一時保持、5種のフィルタ、一括判断、原子的適用、カスタム値 |
| 19.6 | 表示と保存に共通の有効性検査。保存時に再検証 |
| 19.7 | Rustで単語差分を生成し、追加/削除の注記でインライン表示 |
| 19.8 | 著者順序・ORCID、識別子の表示。タグ集合・添付ハッシュは比較関数とテスト |
| 19.9 | Base/Local/Remoteの型付き改訂比較と共通祖先検査。同期・Three-way実画面は対象外 |
| 19.10 | 単体/SQLite/アプリ/実要素テスト、長文と100件の候補、WSLg実描画 |

タグ・添付の登録/保存/UIは別工程のまま。著者のカスタム入力は既存の文献編集画面を使用する。
これらの範囲はユーザー承認済みであり、登録機能や同期を実装済みとは扱わない。

## 判断と保存

「提案値を採用」「現在値を維持」「値を編集」（カスタム値）「判断を取り消す」（未判断へ戻す）は画面上の判断だけを変更する。
「判断を適用」で判断済みの項目だけを一つのトランザクションへ送る。未判断は保留する。
フィルタの判断済み/未判断は、この画面でまだ保存していない判断を指す。適用済みの提案履歴一覧ではない。
フィルタの「すべて」は現在の承認待ち比較対象すべてを意味し、外部が提示しなかった項目の削除行は作らない。
保存した提案・解決・改訂・イベントの履歴は既存のSQL契約に従って保持する。

元モデルは全提案と判断を持ち、表示用モデルだけを絞り込む。隠れた判断は適用対象に含まれる。
フィルタが変わらず同じ提案IDが並ぶ場合は行を更新し、入力中のカードを作り直さない。
Slintのchanged通知はフィルタ変更をRustへ伝えるために使い、比較・永続化の計算をSlintへ置かない。
未保存の判断は既存の破棄確認に含める。表示更新/文献移動の読込失敗では元の判断を保持する。
出力画面を一時的に開いて戻る場合も判断を保持する。

一括採用は要確認でない未判断項目だけ。手動出典、複数head、競合・新旧不明、関連付け、
識別子、明示的削除、正規版切替を自動で選ばない。削除理由が手動値上書きの理由を置き換えていても、
現在改訂の出典を見て保護する。対象0件の場合もステータスへ結果を表示する。
「すべて維持」は提案を拒否する判断、「リセット」は未判断へ戻す操作である。一括採用のボタン名は「安全な項目を採用」。

同じ項目の複数採用・複数の正規版切替・未知のID・重複IDは適用前に拒否する。
拒否、項目採用、正規版切替の順で実行し、正規版切替と各項目の判断を混同しない。
正規版切替で新たに生じる差分は、再読込後に別の提案として確認する。

## カスタム入力

文字列項目、年/月、DOI/arXivを対応対象とする。PublicationType/著者/編集者/KeywordsのカスタムUIは提供しない。
空入力は明示的クリア。出版年は既存画面と同じ1〜65535、月は1〜12。識別子は既存の正規化・検証型で読む。
識別子入力では編集対象のDOI/arXivだけを変更し、ISBN/ISSN/URLを保持する。
元の現在値/提案値の表示文字列は保存値として読み戻さず、提案IDと既存の型付き値を使う。
カスタム値はユーザー入力専用の値として解析し、既存の文献検証を通す。手動の新しい改訂として記録する。
不正入力・競合・DB失敗では、全体を保存せず判断と入力を保持する。
保存成功後の再読込失敗は既存のload-required状態とし、再適用を無効化して表示更新を要求する。

## Staleと有効性

SQLiteの照会トランザクションで、対象文献・削除状態・現在head・候補改訂の対象・候補版snapshot・
候補文献/識別子の同一性・正規版の期待値を確認し、適用不可理由を表示する。
保存時には同じ検査をトランザクション内で再実行する。画面のenabledだけを信用しない。
アプリ層は画面読込時のPaperEditState全体とも照合するため、別項目の編集も見逃して古い画面から保存しない。
同一解決の再送は既存保存APIの冪等性を維持し、別の解決への再送は拒否する。
古い提案は採用/カスタム値を禁止し、最新表示と候補の再評価を要求する。拒否は新しい状態を読んで行える。

## 表示用差分

単語・空白・記号をトークン化し、LCSでEqual/Insert/DeleteのDiffSegmentを生成する。
Myers/Patienceやsimilarの導入も選択肢だが、初期版は計算量を固定上限で抑えられる小さいLCSを選んだ。
各側8192 UTF-8 bytes/128トークンまでで、最大128×128セル。上限超過は左右比較への案内を表示する。
追加は【＋…】、削除は【−…】という表示用注記で、原文と注記は元の左右比較で区別できる。
Slintの部分書式やHTMLへ依存せず、通常の折り返しTextで描画する。GUI専用依存をcoreへ加えない。
この差分は改訂/提案IDに対応する行の表示だけに使用し、採用・競合・同一性の判定には使用しない。
長文の初期本文は600文字のプレビューとし、全文を明示的に展開できる。

著者は現在/提案とも番号付きでORCIDを表示する。完全一致または一意に対応する同じORCIDを手がかりに順序・表記変更を表示する。
同じ名前でORCIDが増減/変更した場合は追加/削除と同一性未確定の注記を出し、名前の類似性だけで統合しない。
重複するORCIDでは対応を決めつけない。著者要約は各側128件まで、それ以上は順序付き本文で確認する。
タグ集合は重複を無視した追加/削除、添付はcontent_hashによる実体変更とファイル名等の変更を別々に返す。

## Three-wayの準備

ThreeWayFieldComparisonはBase/Local/RemoteのFieldRevisionそのものと値比較を保持する。
同じpaper/version/fieldを検証し、供給された親ID履歴から共通祖先へ到達できる場合だけ比較する。
同じRevisionIdに異なる内容がある場合、履歴が不足する場合、対象が異なる場合は比較を拒否する。
Localのみ変更、Remoteのみ変更、同じ変更、双方が異なる変更をテストデータで検証する。
これは比較結果であり、書込・同期・競合解決命令ではない。著者/Keywords/識別子は別の項目固有ポリシーが必要であると明示する。
タグ・添付・論理削除を一般スカラーと同じ規則で自動マージしない。同期転送、祖先取得、Three-way実画面は将来工程。

## 検証

- core: field_diff_contract、structured_diff_contract、revision_comparison_contract。
- storage: candidate_contract（同一性変更でも採用不可表示/保存拒否、既存のstale・重複解決・履歴）。
- desktop: metadata_text_diff_contract（両側の原文再構築、Unicode、上限）。
- desktop: metadata_resolution_contract（部分適用、カスタム入力、未知/重複ID、古い画面、遅延SQL失敗の原子性）。
- desktop: metadata_resolution_window_contract（フィルタ/100件/判断保持/失敗/破棄確認/一括採用保護）。
- 既存のmetadata_window_contract、metadata_diff_window_contract、編集・取得・出力・画面遷移契約も継続実行する。
- WSLgの実ワーカーで、差分表示→カスタム入力→検証エラー→入力修正→狭幅→一括適用を操作・描画確認する。
