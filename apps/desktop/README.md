# paper-desktop

Paper Inbox の Slint デスクトップ UI です。導入、起動方法、保存先、実装状況は[ルート README](../../README.md)を参照してください。

## 画面と操作

折り畳み可能な左メニュー、中央の文献一覧、右の詳細・入力フォームの三列構成です。文献カードのクリックで読取専用の詳細を開き、「編集」でフォームへ移ります。新規登録は直接フォームを開きます。正常な保存・再読込後は閲覧へ戻り、失敗時は入力を保持します。同じカードの再クリックでは編集を保持し、別文献への移動では未保存入力を確認します。最小ウィンドウサイズは 1080 × 680 論理ピクセルです。

左メニューから DOI / arXiv の取得登録、手動登録、削除済み一覧、BibTeX 出力を開けます。取得結果・候補・版の確認は右欄で行い、一覧は表示し続けます。出力対象のチェックと、詳細を開く文献の選択は独立しています。「このアプリについて」には独自コードのライセンスと Slint の謝辞を表示します。

## 実装上の契約

- DB と外部 API の処理はワーカースレッドで行います。失敗時には入力を残し、処理中の重複操作を防ぎます。
- 保存時は変更した項目だけを一括トランザクションで更新します。画面を開いた時点の文献・全項目の履歴との競合を検査します。
- 保存成功後に再読込だけが失敗した場合は、その状態を明示し、再読込まで重複保存を防ぎます。
- 入力・候補・取得結果が未保存の場合、移動・再接続・終了前に破棄確認を行います。削除は別途確認し、復元できます。
- 画面にない書誌項目や、不正な既存識別子は、関係のない項目を編集しても保持します。不正な識別子は警告し、修正できます。

書誌情報取得・引用キーは[取得仕様](../../docs/metadata-lookup-and-keys.md)、承認は[候補・版の仕様](../../docs/metadata-candidates.md)、保存は[保存層の契約](../../docs/storage-contracts.md)を参照してください。

## 検証

```sh
cargo test -p paper-desktop --locked
```

実ファイルの保存・再起動・競合・出力と、Slint の実コールバック／ワーカーを使う画面テストがあります。`layout_window_contract` は画面要素の位置からポインター入力を送り、カード選択、折り畳み、未保存保護、出力チェックの独立性と配置を検証します。開発ビルドはこの試験用の Slint 情報を出力します。

## ライセンス

独自コード: [MIT](../../LICENSE-MIT) OR [Apache-2.0](../../LICENSE-APACHE)。Slint と他の依存関係は[第三者ライセンス](../../docs/licenses.md)を参照してください。

UIの編集フォームは `components/paper-editor.slint`、閲覧は `components/paper-detail.slint` へ分離しています。編集データはMainWindowと双方向に共有し、保存・取消・削除復元の判断とRust接続はMainWindowに残します。`editor_window_contract` は入力、著者3形式の順序と行操作、保存失敗、取消、競合、削除復元、新規遷移を検証します。`pane_layout_contract` はSplitterの実入力と狭い幅での長文カードを検証します。

Step 10〜13で著者・一覧・取得・候補・提案・出力とダイアログを分離しました。MainWindowの `detail-view` が右欄を一意に選択し、RustもSlint生成 `DetailView` を使います。旧表示フラグは読取専用の派生値です。出力設定とpreviewは戻り先を保持するため、編集中の候補や取得入力から一時的に出力へ移ってもdraftを保てます。`detail_view_window_contract` で実際の排他表示・入れ子の戻り先・失敗した移動での入力保持を確認しています。詳細は[UI設計](../../docs/ui-design.md)を参照してください。
